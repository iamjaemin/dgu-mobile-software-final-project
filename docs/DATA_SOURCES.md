# 데이터 출처 및 통합 기준

## 원본 출처

| ID | 제공 자료 | 출처 | 제공받은 파일 | 행 수 |
| --- | --- | --- | --- | ---: |
| mfds_xlsx | 식품의약품안전처 음식 DB | [K-FIND DB 내려받기](https://various.foodsafetykorea.go.kr/nutrient/general/down/historyList.do) | `20251229_음식DB 19495건.xlsx` | 19,495 |
| data_go_kr_json | 전국통합식품영양성분정보(음식)표준데이터 | [공공데이터포털 15100070](https://www.data.go.kr/data/15100070/standard.do) | `전국통합식품영양성분정보_음식_표준데이터.json` | 19,738 |

사용자가 제공한 Downloads의 두 파일을 읽었으며 원본을 수정하거나 최신 파일로 교체하지 않았다. 두 번째 파일의 한글 파일명은 실제 디스크에서 NFD 자모 형태다. 정확한 원본 파일명과 SHA-256은 [manifest.json](../data/processed/manifest.json)에 기록했다. Excel 첫 행은 헤더이고 데이터는 2행부터다. JSON은 `records` 배열의 1부터 시작하는 위치로 행을 표시한다.

웹 출처는 2026-11-11 확인했다. K-FIND는 Excel 내려받기를 제공한다. 공공데이터포털 상세 페이지는 도구에서 직접 열리지 않아 공식 [데이터 카탈로그 메타데이터](https://www.data.go.kr/catalog/15100070/standard.json)로 자료 이름·제공 기관·JSON 제공 형식을 확인했다. 카탈로그는 이용정책 링크를 제공하며, 이용조건은 해당 원본 출처의 정책을 따른다. 파일 내용과 버전은 웹의 최신 목록이 아닌 제공받은 스냅샷 및 해시가 기준이다.

## 선별 기준

사용자가 P002에서 확정한 **앱 공통 필수 필드에 결측치 없는 행** 기준을 적용했다. 원본 전체 열의 완전성을 요구하지 않는다.

- 필수 메타데이터: 식품코드, 식품명, 식품대분류명, 식품기원명, 영양성분함량기준량, 데이터기준일자.
- 필수 영양성분 9종: 에너지, 탄수화물, 단백질, 지방, 당류, 나트륨, 콜레스테롤, 포화지방산, 트랜스지방산.
- 빈 값, 공백, null, `-`, `--`, `N/A`, `NA`, `NaN`, `None`, `미상`, `해당없음` 등은 필수 필드에서 결측치로 취급한다. 대소문자 차이를 무시한다. 실제 측정값 `0`과 `0.00`은 유지한다.
- 영양성분은 유한한 0 이상 숫자만 허용한다. 미량 표시 `Tr`, 검출한계 `<0.1`, 음수, 무한대 등은 숫자로 추정하지 않고 제외 사유를 기록한다. 이번 원본에서 숫자 형식 오류로 제외된 행은 없었다.
- 기준량은 양수 g 또는 mL여야 한다. 이번 선별 결과는 전부 100g 또는 100mL다. mL를 g으로 환산하지 않는다.
- 비타민, 무기질의 나머지 항목, 수분, 식이섬유, 업체명, 식품중량 및 1인(회)분량은 공통 필수 필드가 아니며 통합 JSON에 포함하지 않는다. 해당 항목을 나중에 도입할 때는 다시 선별해야 한다.
- 기준일은 ISO 날짜로 통일한다. Excel의 날짜 일련번호 `46020`은 Windows 날짜 체계에서 `2025-12-29`로 해석한다. 1904 날짜 체계 및 수식 셀은 자동 처리하지 않고 오류로 중단해 검토하게 한다.

## 통합 및 중복 정책

1. 원본별로 필수 필드를 검사한 후 유효한 행을 모은다. 결측치를 다른 출처의 값으로 보충하지 않는다.
2. **식품코드**를 통합 키로 삼는다. 이름이 같아도 코드가 다르면 다른 음식으로 보존한다.
3. 같은 코드에서는 데이터기준일자가 최신인 **완전한 한 행 전체**를 선택한다. 최신 행이 결측치로 제외되었다면 통과한 과거 행을 사용할 수 있다.
4. 기준일이 같으면 공공데이터포털 JSON을 우선한다. 동일 출처·날짜까지 같으면 원본에서 앞에 있는 행을 선택한다. 이 우선순위는 프로젝트의 결정이며 제공기관의 품질 우열을 뜻하지 않는다.
5. 중복된 통과 행의 출처·행 번호를 `sourceRefs`에 모두 저장하고 선택 행만 `selected: true`로 표시한다. 기준일 및 이름을 포함한 차이를 품질 보고서에 보존한다.
6. 식품코드순으로 출력하고 실행 시각·개인 절대경로를 결과 파일에 넣지 않아 동일 입력에서 같은 바이트를 재생성한다.

## 선별 결과

| 구분 | Excel | JSON | 합계 |
| --- | ---: | ---: | ---: |
| 원본 행 | 19,495 | 19,738 | 39,233 |
| 필수 필드 검사 통과 | 2,566 | 2,784 | 5,350 |
| 결측치로 제외 | 16,929 | 16,954 | 33,883 |

중복 2,566행을 정리한 최종 결과는 **2,784개**다. 100g 음식 2,493개와 100mL 음료 291개를 포함한다. Excel의 통과 코드는 JSON에 모두 존재한다. 최신 기준일 `2026-09-29`의 JSON 행이 전부 선택되었고 Excel 참조도 보존했다. 즉, 두 원본을 통합했지만 이번 스냅샷에서는 Excel만의 추가 통과 음식은 없다.

중복 코드 2,566개는 기준일이 다르고 그중 8개는 이름도 다르다. **선택한 9종 영양소·기준량·단위의 충돌은 없다.** 보고서의 `conflicts`는 영양소 불일치뿐 아니라 날짜·이름 차이도 포함하는 버전 차이 목록이다.

주요 제외 필드는 트랜스지방산(Excel 16,769행 / JSON 16,793행), 콜레스테롤(13,461 / 13,486), 지방(13,300 / 13,319), 탄수화물(12,758 / 12,777)이다. 한 행이 여러 사유로 제외되므로 사유별 건수의 합은 제외 행 수와 다를 수 있다. 모든 필드별 건수는 매니페스트에서 확인한다.

## 통합 JSON 계약

파일: [foods.json](../data/processed/foods.json). 최상위 `schemaVersion: 1`, `foods: [...]`.

| JSON 필드 | 원본 필드/의미 | 타입 및 단위 |
| --- | --- | --- |
| code | 식품코드, 고유 키 | String |
| name | 식품명 | String |
| category | 식품대분류명 | String |
| origin | 식품기원명 | String |
| referenceDate | 데이터기준일자 | ISO 날짜 String |
| basisAmount | 영양성분함량기준량의 수치 | Number, 양수 |
| basisUnit | 영양성분함량기준량의 단위 | `g` 또는 `mL` |
| nutrients.energyKcal | 에너지(kcal) | Number, kcal |
| nutrients.carbohydrateG | 탄수화물(g) | Number, g |
| nutrients.proteinG | 단백질(g) | Number, g |
| nutrients.fatG | 지방(g) | Number, g |
| nutrients.sugarsG | 당류(g) | Number, g |
| nutrients.sodiumMg | 나트륨(mg) | Number, mg |
| nutrients.cholesterolMg | 콜레스테롤(mg) | Number, mg |
| nutrients.saturatedFatG | 포화지방산(g) | Number, g |
| nutrients.transFatG | 트랜스지방산(g) | Number, g |
| sourceRefs | 통과한 원본 참조 목록 | sourceId, row, selected |

영양성분은 `basisAmount` 및 `basisUnit` 기준이다. 영양성분 필드에는 null이나 숫자 문자열이 없다. 섭취량 계산은 단위가 같을 때 `영양소 × 섭취량 / basisAmount`를 적용한다. 예를 들어 국밥_돼지머리는 100g당 137kcal이므로 150g은 205.5kcal다.

## 재생성 및 검증

Python 3 표준 라이브러리만 필요하며 추가 패키지 설치는 없다. 원본 파일은 저장소에 중복 복사하지 않았다. 두 원본을 보관하고 아래 경로를 환경에 맞게 지정한다.

```sh
python3 scripts/build_food_dataset.py \
  --xlsx '/path/to/20251229_음식DB 19495건.xlsx' \
  --json '/path/to/전국통합식품영양성분정보_음식_표준데이터.json'

python3 -m unittest discover -s scripts -p 'test_*.py' -v
```

기본 출력 디렉터리는 `data/processed`이며 `--output`으로 변경할 수 있다.

- `foods.json`: 앱에서 사용할 통합 음식 목록.
- `manifest.json`: 원본 해시·출처·입력/제외/중복/출력 수·결과 해시.
- `quality_report.json`: 제외된 행별 사유와 중복 버전별 차이·값. 앱에 포함할 필요 없는 검토 자료.

11개 테스트로 필수 필드 결측, 0 보존, 부정확한 숫자 제외, g/mL, Excel 날짜·빈 셀·공유 문자열, 중복 우선순위, 결과 구조와 수량 대사를 검증했다. 최종 2,784개 음식의 25,056개 영양소 값을 선택된 원본 JSON과 별도 대조해 일치를 확인했다. 동일 원본 재생성 시 세 출력 파일의 바이트 일치도 검증했다. 후속 P003의 Android 앱 빌드 및 Compose 화면 검증은 [APP_SPEC.md](APP_SPEC.md)에 기록한다.
