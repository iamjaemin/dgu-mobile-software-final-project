# 식단 기록 앱 구현 범위 (P003)

## 화면

- 식사 입력: 날짜·시간, 조식/중식/석식/간식·음료, 사진 선택, 음식·반찬 여러 항목 검색 추가, 항목 이름 및 섭취량 수정. 입력 즉시 탄수화물·단백질·지방·열량 미리 보기. 저장 전 양수·유한 섭취량과 음식 한 개 이상을 검사한다.
- 식사 목록: 최신 날짜순 사진 카드, 날짜·시간·종류·음식 이름·열량. 날짜별 총 열량과 기록한 끼니 수. 카드를 누르면 저장 당시 항목·섭취량·영양소·열량을 표시한다. 기록 삭제도 지원한다.
- 식사 분석: 선택 날짜의 일별 분석, 오늘 포함 최근 7일 합계 및 날짜별 열량, 최근 한 달 총 열량과 네 종류별 탄단지·열량·횟수. 최근 한 달은 `오늘.minusMonths(1).plusDays(1)`부터 오늘까지이며 범위를 화면에 표시한다. 미래 기록은 오늘 기준 분석에서 제외한다.
- 출처: 앱 안에 식품의약품안전처 K-FIND와 공공데이터포털 원본 링크, 선별 수·기준 및 단위 설명을 표시한다.

## 표현과 계산

흰색 바탕, 주황색 텍스트·테두리·버튼, 카드 단위 구분. 다크 모드와 동적 색상은 적용하지 않는다. 사진은 원래 색을 유지한다. 탄단지 균형은 각 영양소 g 및 4/4/9 환산 에너지 비율로 표시하고 건강 판정이나 개인별 권장량으로 해석하지 않는다. 열량 합계에는 DB 원본 kcal를 사용한다.

음식은 g, 부피 기준 음료는 mL로 입력한다. 밀도 없이 mL를 g으로 바꾸지 않는다. 음식·반찬은 DB 항목과 연결하고 표시 이름을 수정할 수 있다. 분석은 한 번 저장한 식사를 한 끼로 세며 같은 종류를 여러 번 기록하면 각각 센다.

## 저장과 브랜치

음식 JSON은 Android assets로 패키징한다. 식사 기록은 앱 내부 저장소의 AtomicFile JSON에 저장하고 매번 저장 당시 영양소를 보관한다. 쓰기가 실패하면 기존 파일을 보존하고 사용자에게 오류를 표시한다. 사진은 선택 직후 앱 전용 임시 파일로 축소 복사하고 저장 성공 후 기록이 참조한다. 기록 삭제·교체 시 더 이상 참조하지 않는 사진을 정리한다. 외부 저장소 전체 권한 없이 시스템 사진 선택기를 사용한다.

브랜치는 요청대로 저장소 → 계산 → UI 순으로 작업 단위 커밋을 만든다. 이번 세 기능 연결에 필요한 앞 브랜치 커밋만 다음 브랜치에 fast-forward로 반영한다. 최종 통합 앱은 `feature/ui-compose`에서 검증하며 main에는 자동 병합하지 않는다.

## 검증

데이터 변환 기존 테스트, 순수 Kotlin 단위 테스트(양·단위·날짜 경계·0 데이터·종류별 합계), 저장 직렬화 및 재실행 복구 테스트, Compose 입력·목록·상세·출처 테스트와 APK 빌드·lint를 수행한다. 실제 기기/에뮬레이터에서 가능한 범위는 결과와 함께 기록한다.

### 2026-11-11 검증 결과

- `:app:assembleDebug`: 성공. `app/build/outputs/apk/debug/app-debug.apk` 생성.
- `:app:testDebugUnitTest`: 계산 및 분석 6개와 기존 기본 테스트 1개 통과.
- `:app:connectedDebugAndroidTest`: Android 17(API 37.1) Medium_Phone 에뮬레이터에서 7개 통과(저장소·사진 4개, Compose UI 2개, 기존 기본 테스트 1개).
- UI 테스트: DB 검색, 150g 입력 시 205.5kcal 미리보기, 식사 저장·상세, Activity 재생성 후 상세 복원, 삭제 확인, 분석 및 두 출처 화면.
- 저장 테스트: 새로운 저장소 인스턴스에서 동일 기록 복원, 손상된 파일의 오류 처리, 사진 복사 후 원본 삭제 및 참조에 따른 사진 정리.
- `:app:lintDebug`: 오류 0개. 의존성 및 도구의 새 버전 알림 6개가 남아 있으며 이번 구현에서 일괄 업그레이드하지 않았다.
- Python 데이터 테스트 11개 통과. 앱 assets와 선별 JSON의 바이트 일치 확인.
- 실제 실행 화면 캡처로 흰색·주황색 카드, 텍스트, 하단 탐색 및 상태 표시줄 배치를 검토했다. 사진과 시스템 선택기·키보드 등 OS 화면의 색은 원래 표현을 따른다.

최소 API 24 호환을 설정했으며 하위 API 기기의 실행 검증은 아직 하지 않았다. 저장하지 않은 입력 초안은 ViewModel에 유지되어 화면 회전을 견디지만 프로세스 종료 후 복원하지 않는다. 저장한 식사와 사진은 앱 내부 파일에서 복원한다. 외부 시스템 사진 선택기의 실제 갤러리 조작은 자동화하지 않았으며 선택 후 사진 복사·보관 경로를 기기 테스트로 검증했다.
